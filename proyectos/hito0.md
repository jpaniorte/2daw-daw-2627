# Proyecto Intermodular — 2º DAW

## HITO 0
### Repositorio y definición tecnológica del proyecto

---

## Objetivo

Antes de empezar a desarrollar, cada grupo/alumno debe:

- **Crear el repositorio** de código del proyecto
- **Definir por escrito** qué tecnologías se van a usar y por qué

Es la base formal sobre la que se construye el resto del proyecto.
Sin esto, no se puede empezar el **HITO 1**.

---

## Qué hay que entregar

- [ ] **Enlace** al repositorio Git con el fichero `README.md` en la raíz con el contenido requerido

---

## Requisitos del repositorio

| Requisito | Detalle |
|---|---|
| Plataforma | GitHub, GitLab, Bitbucket, Codeberg... |
| Visibilidad | Privada o pública (si privada, profesor como colaborador) |
| Acceso | **HTTPS/token** el acceso por ssh no funcionará con WIFI_EDU |
| Rama principal | `main` |
| Fichero obligatorio | `README.md` en la raíz |

---

## README.md — Apartados obligatorios

1. **Nombre del proyecto**
2. **Descripción** (5-10 líneas: problema, usuario, funcionalidad principal)
3. **Tecnologías a emplear** *(apartado más importante)*

Cada tecnología debe estar **justificada**, no solo nombrada.

---

## Tecnologías a detallar (I)

- **Guía / sistema de diseño**
  Bootstrap, Tailwind, Material Design, propio...

- **Backend**
  Lenguaje + framework (PHP/Laravel, Node/Express, Java/Spring...)

- **Frontend**
 React, Vue, Angular... + bundler si aplica (Vite, Webpack, Parcel, esbuild, ...)

- **Base de datos**
  Motor elegido + justificación relacional / no relacional

---

## Tecnologías a detallar (II)

- **Documentación**
  Markdown en el repo, Swagger/OpenAPI, JSDoc, Javadoc, Wiki...

- **Librerías y dependencias relevantes**
  Autenticación, validación, gráficas, testing, migraciones...

- **Control de versiones y flujo de trabajo**
  Estrategia de ramas, convención de commits

- **Otros (opcional)**
  Docker, CI/CD, entorno de despliegue previsto

---

## Estructura mínima sugerida

```markdown
# Nombre del proyecto

## Descripción
...

## Tecnologías

### Guía de estilo / diseño
### Backend
### Frontend
### Base de datos
### Documentación
### Librerías y dependencias
### Control de versiones
```

---

## Entrega

1. Subir el `README.md` al repositorio (commit y push)
3. Enviar el enlace por el canal indicado por el profesor
